# ADR-0002：医疗辅助与数据治理边界

- 状态：已接受
- 日期：2026-09-09
- 范围：分诊、疾病模型、推荐、医生/医院数据、反馈和日志

## 背景

项目包含症状到疾病类别模型、红旗症状规则、分诊分析和医生/医院推荐。模型报告本身已说明只能用于数据建模或分诊辅助；但系统仍需要把这一边界落实到代码、文案、测试和记录流程中。

## 决定

- 所有医学输出都标记为辅助信息，不使用“确诊”“保证”“最佳医生”等确定性或承诺性表述。
- 红旗症状、输入不足、低置信度和模型不可用优先触发安全降级和人工/专业复核提示。
- 推荐解释必须区分输入事实、数据事实和系统推断。
- 真实患者信息、凭证和敏感日志不得进入仓库、测试快照、历史记录或 `memory.md`。
- 医院、医生、模型和训练数据必须有来源、更新时间、许可证/使用权限和脱敏状态记录。
- 任何改变医学规则、模型、权重、风险等级或医疗文案的工作至少是 `L3`，需要单独计划、样例/反例和 review。

## 影响

这会限制一部分看似更“确定”的产品文案和自动化行为，但能避免演示系统被误解为临床诊断系统，并让未来的合规、医学审核和数据治理有明确入口。

## 验证要求

- 为正常、症状不足、红旗、低置信度、已知疾病和模型不可用场景建立测试样例。
- 检查前端展示没有隐藏或弱化安全提示。
- 检查反馈、日志和文档没有包含敏感值。
