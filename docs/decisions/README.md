# 决策记录（ADR）

决策记录用于保存会影响未来实现的选择，而不是记录每一次编码细节。已接受的决策默认持续有效，除非新增 ADR 明确取代它。

## 状态

- `提议`：正在讨论，不能作为实现依据。
- `已接受`：当前基线，后续工作应遵守。
- `已取代`：被新的 ADR 替代，保留用于历史追溯。
- `已拒绝`：曾经评估但不采用。

## 何时必须写 ADR

- 改变模块边界、数据契约、模型版本、推荐权重或分诊策略。
- 引入数据库、队列、外部服务、认证、隐私处理或部署方式。
- 选择会导致未来迁移成本的框架、依赖或存储方案。
- 发现现有规则与安全、医学或数据来源要求冲突。

## 编写规则

写清背景、选项、决定、理由、影响、风险、回滚/替代路径和验证方式。不要把“因为感觉更好”作为唯一理由，也不要把尚未验证的指标写成事实。
