# ADR-0001：建立可追溯的重构工作流

- 状态：已接受
- 日期：2026-09-09
- 范围：全仓库协作、重构、测试和记录

## 背景

项目目前是功能较多的单体演示系统，已有若干项目 skills，但缺少统一的入口规则、当前状态、计划、决策、风险、历史和质量记录。继续直接重构容易把架构变化、业务变化和数据变化混在一起，导致无法判断回归来自哪里。

## 决定

采用“规则文件 + 结构化记录 + 小步重构 + 质量门禁”的工作流：

1. `AGENTS.md` 作为仓库级协作规则。
2. `docs/` 作为计划、状态、决策、历史、风险和复核的事实入口。
3. 每个重构切片先建立行为基线，再拆分一个边界，再比较验证结果。
4. 医学、模型、数据来源、隐私和生产安全变化必须提升变更等级并单独记录。
5. 每次会话开始恢复上下文，结束时保存非敏感记忆和当前进度。

## 为什么

它能把“代码怎么改”和“为什么这样改”分开保存，减少跨会话丢失信息；小步切片可以缩小回归范围，也能在不改变用户可见行为的情况下逐步拆分单体。

## 影响

- 文档和记录会成为正常交付物，不再是可选的会后总结。
- 未来的每个功能和重构切片都要带验证结果和剩余风险。
- 初期会增加少量记录成本，但能降低医疗逻辑和大规模数据变更的返工成本。

## 回滚

工作流文件本身可以通过 Git 提交回滚；任何代码重构仍必须使用独立提交和可回退切片，不允许通过回滚工作流文件来绕过安全门禁。
