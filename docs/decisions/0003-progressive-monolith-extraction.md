# ADR-0003：采用渐进式单体拆分

- 状态：已完成（2026-09-11 收口）
- 日期：2026-09-09
- 范围：`app.py`、`static/js/app.js`、`static/css/style.css` 和数据加载边界

> 本 ADR 记录渐进拆分阶段的约束；当前正式边界以 `docs/architecture/current-state.md` 和 `docs/plans/FINAL_REFACTOR.md` 为准。

## 背景

后端和前端都是大文件单体，且缺少自动化回归测试。一次性重写会同时改变路由、推荐算法、状态管理和 UI，无法可靠定位行为差异。

## 决定

采用以下顺序：

1. 记录 API、关键纯函数、模型输出和页面关键路径的当前行为。
2. 先抽取低风险的数据加载和纯函数模块，保持旧入口兼容。
3. 再抽取症状/分诊和推荐应用服务，保留明确的模型适配器。
4. 抽取 API client、页面控制器和可复用前端渲染器。
5. 每个边界完成回归后，才删除重复旧路径。

暂不在首轮引入大型前端框架、数据库或微服务；这些属于另一个需要评估的决策。

## 理由

当前最缺的是可验证边界，而不是更多基础设施。渐进拆分可以把每次变化限制在一个责任范围内，同时保留演示系统可运行。

## 退出条件

只有当接口契约、纯函数结果、模型版本和页面关键流程都有足够测试后，才允许讨论大规模框架迁移或服务化。
