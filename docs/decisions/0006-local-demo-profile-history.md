# ADR-0006：本地演示资料仅保存脱敏分析摘要

状态：已接受  
日期：2026-09-11  
范围：React 并行前端 F11 Profile/History

## 背景

重构提示词要求提供 Profile/History 体验，但仓库规则禁止引入真实患者身份信息、病历、联系方式或未脱敏日志。新前端当前没有账号体系，继续把输入文本留在页面 state 之外会扩大隐私边界，也无法形成可审计的演示约束。

## 决策

- Profile 页明确是“本地演示资料”，不提供登录和身份字段。
- 分析历史默认关闭；用户主动开启后，使用版本化浏览器本地存储，最多保留 8 条摘要。
- 历史白名单仅包含时间、固定 `common` 场景、服务端分诊状态/标签和匹配科室；原始症状、追问答案、模型原文、推荐解释和资源详情不进入 schema。
- 页面必须说明数据只保存在当前浏览器，并提供关闭记录和二次确认清除。
- localStorage 读取/解析/写入异常统一降级，不阻断分诊流程；不把本地历史当作医学事实或云端账户数据。

## 影响

正向影响：完成 F11 的可演示路径，减少输入文本持久化风险，边界可通过源码和测试复核。代价是历史只能显示粗粒度摘要，不能恢复完整会话；跨设备、账号和云端历史明确留到 L4 隐私/认证评审之后。

## 未决事项

若未来需要真实账户、跨设备同步或患者相关数据，必须另立 L4 计划，完成隐私、安全、权限、审计和领域评审，不能沿用本 ADR 的本地 demo 约束直接扩展。
