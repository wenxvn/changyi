# 项目工作流入口

本目录保存重构过程中的“为什么、现在是什么状态、接下来怎么做、如何验证和出了问题怎么办”。代码是运行事实，本文档是协作和决策事实；二者不一致时必须通过决策记录解决，不能靠记忆解释。

## 标准流程

1. **恢复上下文**：阅读 `AGENTS.md`、`memory.md`、`status/current.md` 和当前计划。
2. **定义任务**：写清目标、非目标、验收标准、变更等级和回滚方式。
3. **对齐方案**：架构或行为变化先记录术语、选项、决策和假设。
4. **建立基线**：对要拆分的接口、函数、模型输出和关键页面先添加表征测试或快照。
5. **小步实施**：每个切片只改变一个边界，保持旧入口可用。
6. **验证复核**：运行质量门禁，按 `review` skill 做三层复核。
7. **记录交付**：更新进度、历史、风险、ADR 和 `memory.md`。
8. **提交发布**：使用小而明确的提交；需要远端发布时再由用户明确授权推送。

## 目录索引

| 目录 | 内容 | 更新时机 |
| --- | --- | --- |
| `project/` | 项目章程、目标、约束 | 项目目标或边界变化 |
| `architecture/` | 当前架构和目标架构 | 模块边界、数据流或部署方式变化 |
| `decisions/` | 已接受的重大决策（ADR） | 选择会影响未来实现的方案时 |
| `history/` | 按日期记录的重要事件和复盘 | 完成里程碑、失败、重置或外部变化 |
| `progress/` | 当前状态、里程碑、下一步 | 每个工作切片结束时 |
| `plans/` | 任务计划和重构路线图 | 开始新任务或改变执行顺序时 |
| `risks/` | 风险登记、缓解措施和负责人 | 发现、变化或关闭风险时 |
| `quality/` | 测试策略、质量门禁和验收标准 | 验证方式变化时 |
| `reviews/` | review 报告和待处理问题 | 每个功能或切片完成时 |
| `templates/` | 新记录的统一模板 | 模板结构变化时 |

## 命名约定

- 日期统一使用 `YYYY-MM-DD`，以项目时区 Asia/Shanghai 记录。
- 决策使用 `NNNN-short-name.md`，编号只递增不复用。
- 计划使用 `YYYY-MM-DD-short-name.md`。
- 风险使用 `R-###`，事件使用 `H-YYYYMMDD-###`，进度快照使用 `P-YYYYMMDD-###`。
- 状态只使用：`待开始`、`进行中`、`阻塞`、`已完成`、`已废弃`。
