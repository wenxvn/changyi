# 医院候选遍历边界计划

状态：已完成

## 目标

把医院推荐中“逐医院准备距离、可达性和交通展示上下文并调用单候选组合”的 orchestration 提取到 `backend.app.domain.recommendation.candidate`，让 `app.py` 只提供兼容数据和显式回调，再执行既有 rerank。

## 非目标

- 不改变医院候选全集、距离函数、交通缓存、可达性权重、急症交通旁路或 rerank 约束。
- 不改变医院 feature、风险惩罚、解释、结果字段、模型版本或医学文案。
- 不把交通样本加载、实时新鲜度、医院 provenance 或临床能力判断伪装成 domain 事实。

## 步骤

- [x] 在 `candidate.py` 新增显式回调的医院候选遍历函数。
- [x] 用函数替换 `app.py` 医院推荐中的逐医院循环。
- [x] 增加 first_visit/urgent 交通 ranking policy 和候选顺序测试。
- [x] 更新进度、历史、复核、状态、架构、迁移和风险记录。

## 验收与回滚

- 对同一医院列表、位置、triage、交通访问和组合回调，候选字段与顺序保持一致。
- 全量 pytest、Safety Eval、API smoke、编译检查、数据校验、快照和 diff check 通过。
- 回滚方式：恢复 `app.py` 医院逐候选循环并移除本切片函数、测试和记录。

## 风险

该切片是 L2/L3 边界附近的结构性迁移；回调仍代表演示系统已有数据与规则，不能把交通可达性或医院排序解释为实时接诊、诊断或临床决策。
