# 常医智导前端迁移计划：医疗资源浏览首版

状态：进行中（首版）  
日期：2026-09-10  
变更等级：L2（只读资源 API、前端检索状态和资料预览；不改变医学规则或推荐排序）

## 目标

在并行 `frontend/` 中把“医疗资源”从占位页推进为可浏览的医院/医生资源索引，支持搜索、类型切换、资料预览和来源状态提示。医院和医生数据只从既有 `/api/v1/hospitals`、`/api/v1/doctors` 读取。

## 非目标

- 不在前端复制分诊、疾病识别、推荐排序或急症判断。
- 不把旧医院常量的 `legacy_catalog_pending_provenance` 包装成已验证官方资料。
- 不新增真实定位、地图、收藏、预约、电话外呼或生产登录。
- 不修改 legacy `/`、旧 API 或现有推荐快照。

## 关键决策

- 资源页首屏只请求医院索引；切换到医生后才请求医生索引，避免首页和首屏加载 2,100 条医生记录。
- 搜索和类型过滤只用于展示层筛选；没有匹配时明确显示空态，不推断资源不存在。
- 资料预览只展示接口中有明确字段的数据；来源状态与“公开资料/迁移待补齐”文案同时出现。
- 地图入口仍跳转到明确标记为建设中的地图页，不能用普通资源列表冒充附近急诊。

## 实施步骤

1. 扩展资源 API 类型、运行时 schema 和单一 client 调用。
2. 实现资源索引页、医院/医生卡片、搜索、分页式展示上限和资料预览。
3. 接入 App Shell 的 `/resources` 路由，保留 `/map` 占位边界。
4. 增加资源 schema/边界测试，运行 typecheck、build、pytest 和浏览器 desktop/mobile 检查。
5. 同步 architecture、contract、UI registry、status、progress、history 和 review。

## 验收标准

- `/resources` 可加载医院索引，网络错误和空列表有明确状态。
- 切换医生时才请求医生索引；搜索医院名称/地址/科室、医生姓名/医院/科室/专长可用。
- 卡片展示公开资料字段、医院/医生类型和来源状态；不展示推荐分或学术成就作为排序依据。
- 移动端无横向溢出，资料预览可在卡片列表后阅读；地图入口明确为后续能力。
- legacy 默认入口和后端医学/推荐行为不变。

## 回滚

回退本计划新增的 `frontend` 资源页、资源 API client/schema 和对应文档即可；不影响 Flask 默认 `/`、旧 API 与既有 v1 triage/recommendation。
