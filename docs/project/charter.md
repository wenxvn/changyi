# 项目章程

## 项目名称

常州市智能医疗推荐系统（常医）

## 当前定位

一个面向医疗资源检索、分诊辅助和可解释推荐的演示型 Web 系统。系统通过医院和医生数据、症状标准化、疾病类别模型、就诊场景、位置和交通可达性生成辅助信息。

## 目标

- 让用户能够从症状或病情描述进入医院、科室和医生推荐流程。
- 让推荐结果展示可理解的匹配依据、风险提示、距离和资源信息。
- 让数据、模型和前端交互可以独立验证、更新和回滚。
- 在重构过程中保持现有演示能力和 API 兼容性，减少大范围回归风险。

## 非目标

- 临床诊断、处方、急救指令或对医生作出替代性判断。
- 证明模型能用于真实临床；当前模型指标只代表现有样本和评估切分。
- 未经合规、隐私和安全审查的生产部署。
- 在一次重构中同时改变业务策略、数据口径、视觉风格和部署架构。

## 主要使用者

- 演示或评审人员：查看系统能力和推荐解释。
- 数据/模型维护者：维护医院、医生、交通和症状模型数据。
- 开发者：拆分单体、补充测试、维护 API 和前端交互。
- 未来的业务或医学审核者：审核规则、红旗症状、数据来源和风险边界。

## 已知约束

- 当前后端主要集中在 `app.py`，前端主要集中在 `static/js/app.js` 和 `static/css/style.css`。
- 数据直接从本地 JSON/CSV 和静态资源目录加载，尚无数据库或正式数据管线。
- `requirements.txt` 只有 Flask 和 Flask-CORS，尚无正式测试依赖和 CI 配置。
- 当前存在演示登录和本地 CORS 行为，不能视作生产级认证或访问控制。
- 静态资源体量较大，数据源、许可证、版本和更新策略需要进一步制度化。

## 成功标准

重构完成的定义不是“目录看起来更漂亮”，而是：

1. 关键 API 和页面行为有可重复的基线。
2. 业务规则、模型调用、数据读取和路由边界可单独测试。
3. 医学安全降级、红旗症状、低置信度和人工复核路径可验证。
4. 数据来源、更新时间、许可证、脱敏状态和变更历史清楚。
5. 每个重构切片都能通过质量门禁并可回滚。
