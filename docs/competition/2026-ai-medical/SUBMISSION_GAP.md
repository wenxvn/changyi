## 现状结论

- **工程与安全不是短板**：`/api/v1`、Safety-first publication、142-case Safety Evaluation、Grouped Near-Duplicate CV、分层测试与 Flask-served React demo 已可演示。
- **短板是「按赛题规范把证据打包成可评审作品」**：初赛主材料（技术方案 / 视频 / PPT PDF / 简介 / 佐证 / 网盘包）均未按规范产出。
- **存在事实与文档漂移风险**：旧 PPT 与部分文档数字/能力描述落后于当前基线，若原样提交会在形式审查或答辩中被追问。

粗判落点（非官方评分，仅内部优先级参考）：创新 12–16 / 需求 5–9 / AI 技术 11–15 / 实施 10–14 / 成效 6–10 / 总结 4–7 / 附加 0–2。  
**现在直接交初赛，形式审查风险高，材料分会被明显压低。**

## 赛前禁止事项

1. 把固定样例 Safety 指标写成「临床准确率 / 诊断正确率」。
2. 把 random split Top-1 `0.973` 作为主指标宣传；必须同时给出 grouped / near-duplicate 隔离结果与限制。
3. 在材料中出现学校、学院 LOGO、指导教师、真实患者身份或未脱敏日志。
4. 把 `demo_only` / `provisional` / 无来源派生分数写成官方事实。
5. 为冲分静默修改红旗规则、分诊阈值或 Safety 基线（必须 L3 + 评估回归）。

## 回滚与边界

本审计与后续提交工作只产出文档与打包物，不修改运行时医学行为。若技术方案/PPT 中的数字与仓库不一致，**以仓库可运行评估结果为准**并改文档，禁止反向改评估脚本去迁就文稿。
