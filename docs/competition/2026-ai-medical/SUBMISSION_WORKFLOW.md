# 竞赛提交工作流（2026 AI+医学 · 初赛）

更新时间：2026-09-15  
适用：初赛材料准备与形式审查自检。复赛/总决赛材料在初赛包冻结后另开阶段。  
差距详情：[`SUBMISSION_GAP.md`](SUBMISSION_GAP.md)

## 阶段门禁

```text
S0 冻结叙事  →  S1 证据对齐  →  S2 技术方案  →  S3 演示视频
     →  S4 答辩 PPT PDF  →  S5 佐证与 LICENSE  →  S6 匿名与数字审计
     →  S7 网盘打包  →  S8 报名系统提交  →  S9 冻结
```

任一门禁失败：停止进入下一阶段；**禁止**为通过门禁修改 Safety/医学规则或评估口径。

| 阶段 | 目标 | 输入 | 完成定义 | 失败回滚 |
| --- | --- | --- | --- | --- |
| S0 冻结叙事 | 作品名、一句话定位、三创新点、非目标 | `COMPETITION_BRIEF.md`、P4 产品现状 | 名称 ≤20 字；简介草稿 ≤300 字；禁止诊断/AI 医生表述 | 改叙事，不改代码 |
| S1 证据对齐 | 所有对外数字可回到仓库 | Safety/模型/数据报告、`docs/status/current.md` | README/MODEL_CARD/SCORECARD/status 数字一致；主指标使用 grouped/安全集，不单用 random Top-1 | 修文档，不修评估脚本迁就文稿 |
| S2 技术方案 | 官方大纲 PDF | 官方模板 + S0/S1 | 正文 ≤8000 字；PDF ≤10MB；含需求、方法、安全、数据限制、评估、局限展望 | 退回 S1 补证据 |
| S3 演示视频 | 3–5 分钟 MP4 | `DEMO_SCRIPT.md`、运行中 Demo | 时长合规；≤300MB；三案例；无学校/导师；字幕与 UI 无建设中空洞误导 | 重录或剪掉未完成路径 |
| S4 答辩 PPT | 与技术方案同口径 PDF | S2 章节、当前 UI 截图 | 概括作品/背景/技术/创新/前景；无过期能力与无来源大数字 | 从 S2 重抽大纲 |
| S5 佐证与许可 | 佐证 PDF + LICENSE | 评估导出、质量报告、（如有）证书 | 佐证合并单 PDF；代码 LICENSE；数据限制可引用 | 补文件，不伪造证书 |
| S6 匿名与数字审计 | 形式审查自检 | S2–S5 全部产物 | 清单见下文「审计清单」全绿；留审计记录 | 删改违规内容后重审 |
| S7 网盘打包 | 可分享材料包 | S2–S5 | 命名规范；永久有效+自动提取码；链接列表 | 重新分享 |
| S8 系统提交 | 报名系统字段填齐 | S0–S7 | 名称/简介/技术方案/视频/PPT/佐证/链接全部上传 | 截止前重传 |
| S9 冻结 | 初赛包不可再改语义 | 提交回执 | git tag 或 `submission/` 清单快照；只允许错别字级修复策略（若规则仍开放修改） | 按组委会规则处理 |

## 演示视频脚本锚点（与 `DEMO_SCRIPT.md` 对齐）

1. **问题 10s**：信息过载 vs 安全优先的就医决策。
2. **普通病例 ~45s**：否定理解 → `ROUTINE` → 科室/医院 → 为什么推荐。
3. **信息不足 ~45s**：有限追问；强调不是诊断。
4. **急症 ~60s**：Safety Gate 先置；120；不出现普通排行榜主视觉。
5. **可信证据 ~30s**：Trust/Evidence 页展示来源、版本、限制、Safety 指标出处。
6. **边界 10s**：演示辅助系统，不替代医生；实时急诊/导航非目标。

总时长目标：**约 3.5 分钟**（留剪辑余量进 3–5 分钟带）。

## 审计清单（S6）

### 匿名与合规

- [ ] PPT / 视频帧 / 字幕 / 截图 / 网盘文件名 / 报名字段无学校、学院 LOGO、指导教师、学号、班级
- [ ] 无真实患者姓名、身份证、手机号、病历号
- [ ] 无未授权第三方素材水印或版权不明图片
- [ ] 医学表述均为「辅助 / 参考 / 非诊断」；红旗与 120 优先未被弱化

### 数字与事实

- [ ] Safety：142 cases；Recall 1.0；Under-triage 0；Over-triage 0；Emergency FN 0（以最近一次 `evaluate_safety` 为准）
- [ ] 模型：主叙述使用 grouped / near-duplicate 隔离与限制；不把 Top-1 0.973 写成临床准确率
- [ ] 数据：21 家医院等公开事实与 `provisional` 限制同时出现；无来源大数字已删除
- [ ] 测试基线：pytest / boundary / Playwright 数字与 `docs/status/current.md` 一致
- [ ] 材料间同一事实只有一种写法（技术方案 = PPT = 视频口播 = README）

### 文件规范

- [ ] 技术方案 PDF ≤10MB，正文 ≤8000 字
- [ ] 视频 MP4，3–5 分钟，≤300MB
- [ ] 答辩 PPT 为 PDF
- [ ] 佐证为单一 PDF
- [ ] 网盘命名：`团队编号-赛题名称-作品名称-XX`；永久有效；自动提取码

## 产物目录约定（提交用，不入库大文件）

```text
submission/2026-ai-medical/          # 本地打包目录（gitignore 大媒体）
  00-meta.md                         # 名称、简介、团队编号、网盘链接
  01-技术方案.pdf
  02-演示视频.mp4
  03-答辩PPT.pdf
  04-佐证材料.pdf
  05-anonymity-audit.md              # S6 检查记录
  06-evidence-index.md               # 指向仓库内评估/质量报告路径与 hash
```

大文件默认不进 Git；`00-meta` 与审计记录可进 Git 以便追溯。是否提交 `submission/` 元数据由赛前一次决定写入 `.gitignore`。

## 角色与责任

| 角色 | 责任 |
| --- | --- |
| 叙事 Owner | S0、S2 章节结构、与赛题「AI+医学」主题符合性 |
| 工程 Owner | S1 数字源、Demo 可运行、复现路径 |
| 演示 Owner | S3 视频、S4 PPT 与真实 UI 一致 |
| 审计 Owner | S6 清单；拥有一票否决（匿名/安全表述/假数字） |

小团队可一人多角，但 **S6 审计必须在非撰写视角再跑一遍**（隔天或换人）。

## 与内部质量门禁的关系

- 日常开发仍走 `AGENTS.md` 与 `docs/quality/quality-gates.md`。
- 本工作流只管理**竞赛提交物**；不授权放宽 pytest/Safety/数据质量门禁。
- 若提交叙事需要新指标：先在仓库生成可复现结果，再写入材料；禁止先写材料再补数。
