### 一、项目概述（900 字）

#### （一）项目背景与意义（600 字）

写作顺序：**现象 → 断点 → 后果 → 为什么现在能做**。

1. **现象**：常见非急症就医要先完成四次决策（要不要去、挂哪个科、去哪家、怎么去），每次决策都要求用户具备它并不具备的医学词汇。
2. **断点**：现有工具各自只覆盖一段——搜索引擎给信息不给路径，挂号平台要求先知道科室，地图只解决最后一段。分段之间没有状态传递。
3. **后果**：两类风险。轻的一类是挂错科、反复转诊；重的一类是红旗症状被当成普通不适，进入错误的低优先级路径。
4. **为什么现在能做**：城市级医疗资源已以结构化目录形式公开；稀疏文本模型在 CPU 上可复现；关键不是模型多大，而是**安全层是否独立于模型**。
5. **意义**：把"选科室/选医院"这个高频、低风险、可结构化的决策从诊断任务里切出来，既降低使用门槛，又不越界。

证据：`data/regions/320400/`（21 家医院、2100 条医生、50 条公交线路）；`COMPETITION_BRIEF.md`。

禁写：不写"缓解看病难""降低医疗成本 X%"，无据；不写全国覆盖。

### 二、需求分析（1300 字）

#### （一）问题剖析（750 字）

这是 15 分里"剖析是否深入"的落点。用**四层拆解**，每层给一个可验证的技术后果：

| 层 | 问题 | 技术后果 |
| --- | --- | --- |
| 语言层 | 口语、否定、假设、既往史混在一起（"没有胸痛""如果疼起来""去年查过"） | 朴素关键词匹配会把否定当阳性、把历史当当前 → 必须有否定窗口与语境识别 |
| 安全层 | 红旗症状与普通症状共享词汇（"喘不上气"既是焦虑也是心衰） | 任何概率模型都可能给出高置信的错误低风险 → 安全判定不能交给模型 |
| 映射层 | 用户要的是"挂哪科"，模型擅长的是"是什么病" | 疾病→科室的间接映射会把错误疾病传导成错误科室（同切分 0.291） → 任务应重构为直接科室路由 |

**关键难点（必须点明）**：安全与智能的目标函数不一致。模型优化平均准确率，医疗场景最不能容忍的是**低概率高后果的错误**。这一句解释了后面所有设计选择。

### 三、AI 技术工具选择与运用（1500 字）

官方此章问的是"**如何选择**"，不是"用了什么"。主体是选型对照表 + 三段论证。

#### 3.1 总体技术栈（300 字）

规则层 + 学习层 + 排序层 + 交付层四段，一张架构图（图 1）带过。强调：**四层是短路关系，不是投票关系**——Safety 命中即终止后续。

#### 3.2 选型对照表（700 字，核心）

| 环节 | 候选 | 选定 | 选它的理由 | 放弃的理由 |
| --- | --- | --- | --- | --- |
| 安全判定 | 规则 / 分类模型 / LLM | **确定性规则 + 四态枚举** | 可枚举、可回归、零训练依赖、可逐条解释 | 模型无法保证"永不漏判"；LLM 不可复现、给不出确定性边界 |
| 科室路由 | 端到端 LLM / 中文编码器（BGE）/ 稀疏 n-gram + 线性模型 | **char n-gram TF-IDF + 逻辑回归** | CPU 可复现、小样本稳定、权重可解释、训练成本近零 | LLM 幻觉且不可审计；编码器需 GPU 与更大标注量，本项目数据不足以支撑 |
| 概率校准 | 无 / 温度缩放 / isotonic / conformal | **温度缩放（单标量）** | 只拟合一个参数、不改变 argmax、cal 上可验证 | isotonic 在小 cal 上过拟合；conformal 交换性未获验证 |
| 拒答策略 | 固定阈值 / cal 分位阈值 / 学习式拒答 | **cal-only 分位阈值** | 阈值只来自 calibration，test 只评估，杜绝调参泄漏 | 固定阈值无法对齐目标 coverage |
| 追问策略 | 信息增益 / 高频优先 / 随机 | **保留 IG 但标注未证实** | IG 有理论依据 | 实测仅比高频高 0.43pp → 诚实降级 |
| 资源排序 | 学习排序 / 规则加权 | **多目标可解释加权 + 缺失降权** | 权重可审计、可消融、缺字段自动降权 | 学习排序需点击数据，本项目没有，硬做即造假 |
| 交付 | 后端模板 / SPA | **Flask + React/Vite，单一 `/api/v1` 边界** | 前后端职责清晰、可独立测试、可静态降级 | 单体模板难维护状态与可访问性 |

#### 3.3 为什么不用端到端大模型（300 字）

正面回答，三条理由，每条给一个可验证后果：

1. **不可审计**：评委问"为什么推荐这个科"，LLM 只能给理由文本，不能给权重与消融。本作品每个推荐都能追到特征与权重。
2. **不可保证优先级**：LLM 的输出分布无法保证"红旗永远压过普通推荐"。本作品用 `safety_first_*` 投影在公共输出边界强制清空模型结论。
3. **不可复现**：同一输入多次调用结果可能不同，无法做回归门禁。本作品每次评估结果写入 JSON 并可 diff。

立场句：**不是排斥大模型，而是当前任务的数据量与安全要求不支持把它放在决策路径上**；它更适合放在"解释改写"这类非决策位置（列为未来工作）。

#### 3.4 工具与环境（200 字）

Python 3.11.9 / Flask 3.1.3 / React 19 / TypeScript / Vite / Playwright / scikit-learn。全部 CPU、本地可复现，无 GPU、无云依赖。附 `PINNED_VERSIONS.md` 版本表。

#### （三）创新性体现（450 字）

用"现有做法 → 本作品 → 可验证差异"三列，写三点，不要超过三点。

1. **安全与模型的结构性分离**：不是"模型里加个安全分类器"，而是模型输出在急症时被强制清空。差异可验证：冲突用例下模型给出普通科室，系统仍输出 EMERGENCY 且疾病候选 abstain（黄金测试锁定）。
2. **任务形态重构**：从"预测疾病"改为"直接预测就医方向"。差异可验证：同一切分下 disease-first 映射（0.291）与直接路由（0.608）的对比。
3. **证据可审计性**：单一证据索引 + 数字漂移检测 + **主动公开负结果**（旧 0.742 不可复现、IG 未优于高频、80% coverage 未达成）。多数作品只报正结果，这一点本身构成方法层面的差异。
