# 常医智导 · 技术报告大纲

2026 AIC · AI+医学。作品名称：常医智导。正文规划8000字，附录单列；提交格式为匿名PDF，文件上限10 MB。章节对应官方《AIC·AI+医学技术报告参考大纲》。

## 作品简介

居民就医前，首先需要知道的是“下一步怎么做”。症状描述、风险判断、科室选择和医院查询之间，缺少一条贯通的行动路径。常医智导以独立安全门统领城市就医辅助：先识别风险，再组织科室方向、医院医生资源与到院入口；危险信号触发优先处置，信息不足触发追问，普通主诉进入资源路径。在142个固定工程样例中，84个红旗样例全部检出，急症漏报为0，7个信息不足样例全部匹配；常州目录连接21家医院和2100条医生资料。作品的核心价值是把安全优先落实到系统输出，把就医方向落实到本地行动。

## 一、项目概述（900字）

### 1.1 背景与问题

就医服务的入口是一段生活语言，医疗资源的入口则是科室、医院和医生目录。居民需要在两者之间完成风险判断与信息转换：是否需要优先就医、应该先了解哪个科室、可以查询哪些本地资源、如何继续到院。这构成城市就医辅助的核心服务需求。

### 1.2 服务缺口与总体思路

病名分类、资源检索和地图导航分别回答不同层次的问题。常医智导围绕“下一步行动”连接这些能力：安全状态决定结果发布方式，科室方向承接主诉，城市目录承接方向，地图承接到院入口。同一主诉和安全状态在整条路径中保持连续。

系统的主张是：**先识别风险，再连接就医行动。** 独立Safety Gate将风险优先级落实为发布规则，解释信息支持用户理解当前方向，Region Pack衔接医疗辅助与城市目录。

### 1.3 核心成果

固定Safety评测包含142例：84个红旗样例全部检出，急症漏报0，信息不足样例7/7匹配。普通主诉、信息不足、急症三类路径，分别对应资源衔接、继续追问和急症优先出口。常州医院目录21条，医生资料2100条；医生资料涉及11家医院、194个科室条目。

Safety数字对应固定工程回归集。作品定位为就医辅助，医疗判断由专业人员承担。

## 二、需求分析（1200字）

### 2.1 以行动为单位的需求结构

| 用户任务 | 服务要求 | 系统响应 |
| --- | --- | --- |
| 描述不适 | 使用生活语言进入服务 | 主诉录入、语境识别、当前理解 |
| 判断优先级 | 危险信号获得优先处理 | 独立安全门与四态发布 |
| 明确就医方向 | 获得可解释的科室参考 | 方向、依据、待补充信息 |
| 查询本地资源 | 方向直接连接医院和医生 | 科室匹配、资源策略、目录检索 |
| 继续到院 | 资源直接连接地理位置 | 医院位置与导航入口 |

### 2.2 安全优先级与个人偏好

风险优先级约束推荐过程。急症分支使用急症策略；普通路径结合科室匹配、可及性和就医偏好组织资源。偏好优化发生在安全约束之内，安全状态在分诊和资源服务中共享。

信息充分度决定输出强度。缺少医学主诉时，系统请求补充信息；具备可解释方向时，系统提供对应资源入口。追问承担澄清任务，使输出与当前信息相匹配。

### 2.3 场景与评价对象

需求依据来自就医任务分析、资源目录结构和合成情境验证。评价对象包括风险分支一致性、方向解释和本地资源衔接。后续场景研究围绕任务完成情况、方向理解一致性和操作步骤展开。

## 三、AI技术工具选择与运用（1600字）

### 3.1 安全控制与方向推断分工

独立规则门负责风险优先级与发布状态，输入理解负责当前性、主体、否定及主诉信息，科室方向和资源服务负责后续衔接。模型适配器处于受约束的服务链内，公共输出由统一发布规则控制。

该分工具有可检查的控制关系：风险信号触发急症分支，信息充分度决定追问或方向发布，资源偏好影响对应分支内的排序。各模块的输入、输出与责任可以分别验证。

### 3.2 技术选型与任务适配

| 环节 | 技术方案 | 对就医辅助的直接价值 |
| --- | --- | --- |
| 风险控制 | 确定性规则、四态枚举、统一发布投影 | 风险优先级可检查、可回归 |
| 输入理解 | 症状归一化、否定与语境识别 | 生活表达转换为可解释证据 |
| 科室分类研究 | 稀疏文本表示、标准分类器、训练内嵌套选择 | 直接围绕科室标签建模 |
| 输出可信度研究 | 校准集拟合、温度缩放、选择性输出 | 既定数据口径下协调输出强度 |
| 资源策略 | 可解释特征与规则约束 | 科室、场景与可及性共同参与资源组织 |
| 产品交付 | React、TypeScript、Flask、统一API | 网页交互与后端安全责任衔接 |

### 3.3 研究评测与产品职责

标准嵌套选择主流程在1289行公开混合文本上，五个seed平均科室分类Acc为94.25%±2.00个百分点，Macro-F1为94.65%，温度校准ECE为0.0321。算法选择在训练内完成，校准集拟合输出参数，测试集承担评估。

该结果对应公开文本科室分类的离线研究。产品安全状态由独立规则门负责，研究模型以 `RESEARCH_ONLY` 状态管理。固定配置Round4和标准嵌套流程按各自协议、数据与分母解释。

资源目录保留公开字段、来源记录、核验状态与许可状态。医院目录为 `provisional`，许可登记情况随数据说明列示。交通样本标记 `rankable=False`，承担展示用途。地图底图署名为 © OpenStreetMap contributors，距离按可获得的位置估算；急诊目录字段描述资源类别，实时接诊情况以医疗机构和急救服务确认为准。

公开研究语料的来源与许可记录见 `round4_report.json` 的 `dataset.provenance`，数据说明沿用对应存档时间及许可口径。参赛截图采用主诉、分诊和地图界面，展示主诉均为合成。

### 4.2 系统架构

React界面调用 `/api/v1`，由Flask应用服务协调领域逻辑、模型适配器与资源仓库。Safety Gate和公共输出投影在后端统一执行，前端展示状态、依据、追问和资源入口。Region Pack独立组织城市资料，区域数据装载与安全逻辑保持清晰边界。

### 4.3 关键机制

| 机制 | 实现关系 | 用户可见结果 |
| --- | --- | --- |
| 风险优先发布 | 急症/及时评估状态控制发布与资源策略 | 风险提示和相应就医入口优先呈现 |
| 信息充分度控制 | 信息不足进入追问；普通路径连接方向 | 输出强度与当前信息相匹配 |
| 方向解释 | 当前理解与科室依据关联 | 用户能查看方向所依赖的信息 |
| 资源策略贯通 | 分诊状态传递给资源服务 | 急症策略优先于普通偏好和重排 |
| 城市目录连接 | 科室关联医院医生，医院连接位置 | 方向可继续进入本地资源和地图 |
| 分层证据 | 安全样例、API、网页、分类研究各有记录 | 每项结果对应实际评价对象 |

### 4.4 交付与运行

Flask服务React构建产物，核心业务通过统一API访问，CPU环境可运行。网页核心体验无需登录，个人收藏与历史保存在浏览器本地。质量验证覆盖安全发布、服务契约、页面交互和数据来源记录。

## 五、研究或应用成效（1600字）

### 5.1 安全约束具有直接、可复核的结果

固定142例包含84例急症、29例及时评估、22例普通路径和7例信息不足情境。红旗召回率1.0，急症漏报0，Under-triage和Over-triage均为0，信息不足样例7/7匹配。结果验证了固定情境中风险优先级与输出分支之间的控制关系。

### 5.2 三类服务路径形成可操作结果

| 合成情境 | 实际输出 | 服务价值 |
| --- | --- | --- |
| 当前胸痛并伴呼吸困难 | `EMERGENCY`，急症优先出口 | 危险信号直接决定页面动作 |
| 年龄、性别信息 | `INSUFFICIENT_INFORMATION`，补充主诉 | 当前信息与输出强度匹配 |
| 皮肤瘙痒一周 | `ROUTINE`，皮肤科方向与资源入口 | 方向继续连接本地就医资源 |

三个示例来自2026-10-22网站合成情境实测。API契约覆盖追问补充、急症资源策略，以及模型冲突时的安全优先发布。

### 5.3 系统优势

**安全优先进入控制链。** 风险级别改变可发布内容及资源策略，使安全成为产品行为的一部分。

**解释直接服务下一步。** 当前理解、科室方向和资源入口保持衔接，用户可以围绕已有信息继续操作。

**城市资源形成服务载体。** 常州21条医院目录和2100条医生资料承接方向查询，Region Pack为其他城市数据接入提供结构。

### 5.4 应用价值与转化场景

作品面向居民自助查询、社区服务导诊和城市医疗资源服务入口。应用评价围绕风险分支一致性、方向依据可理解性、资源路径可继续性展开。场景接入采用经专业审核的使用流程和经核验的城市目录；任务研究评价完成率、步骤数与方向理解一致性。

## 六、总结与展望（500字）

### 6.1 总结

常医智导把居民主诉连接到安全状态、科室方向与城市资源。独立安全门使风险优先级进入发布控制，解释信息支持用户理解当前方向，资源服务让方向继续连接医院、医生与到院入口。固定142例中的84个红旗样例全部检出，急症漏报0；常州21条医院目录与2100条医生资料构成可操作的城市示范。

**安全优先，方向可解释，路径可继续。** 这三点共同构成作品的服务价值，也构成面向新场景复用的系统基础。

### 6.2 展望

场景拓展围绕社区导诊、城市服务入口和多城市Region Pack展开。数据治理、专业审核和任务评价伴随场景接入，模型研究围绕目标输入域与科室标签开展独立评价。核心控制关系保持统一：先识别风险，再连接就医行动。
